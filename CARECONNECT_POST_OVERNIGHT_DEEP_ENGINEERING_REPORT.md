## D. Dotenv incident investigation

The original command was `npx tsx --test tests/*.test.ts`; it discovered `tests/security.test.ts`. That script originally called `dotenv.config()` before checking `SECURITY_TEST_CONFIRM_HOST`. It read URL/key variables and printed a target hostname before refusing. Source control flow puts `createClient` and signup after refusal, so that refusing process could not run those calls. It exited without spawning further application children. The parent test runner does not acquire a child's environment modifications.

The original `npm run build` also loaded dotenv through Vite/shared-plugin definitions and Nitro configuration. VITE-prefixed values can enter built client assets by design. Original file contents, historical network telemetry and every old ignored output are deliberately not inspected, so this report cannot certify that no secret was ever exposed or persisted. No evidence of a hosted mutation was found in the available execution record; this is narrower than a universal network assertion.

The prior fix disabled Vite/shared-plugin loading and the explicit `nitro.config.ts` load, but Nitro's Vite adapter separately invokes c12 dotenv discovery. The first historical draft-reproduction build in this continuation ran before the new guard; that same implicit-loading risk applies to it. A later guarded build failed before the c12 read completed, proving the extra path. This is an additional exposure uncertainty, not a claim that the old isolation was adequate.

Correction: `scripts/deny-local-env.mjs` preloads into safe unit tests and synthetic build/server children. It presents private dotenv/link files as absent to synchronous discovery and throws on attempts to read/open them through supported Node fs APIs. It folds case to protect Windows aliases. Nitro's installed Vite adapter forces discovery without an exposed dotenv-disable option, hence this process-local file boundary. The original files are never renamed/copied/edited. Synthetic sentinel regressions cover sync, promise, stream, case alias and discovery behavior. Later guarded builds successfully compile without permitting private reads.

This preload is a defensive guard for trusted test code, not an OS sandbox against malicious code, alternate syscalls, pre-opened descriptors or symlink aliases. No claim of universal filesystem containment is made. Actual runtime configuration remains separate; live-service smoke is still explicitly selected and was not run.
